# 事件第二批 · 设计稿（2026-10-06）

> **状态**：A / B / C 三组 12 个事件已实现(2026-10-06)，D 组(紫之章颜色事件)按用户意见先不做。实现时和稿子的出入：
> `bench_free` 条件没做(仓库没有上限，"请他上车"不设条件)；`perm` 用 `damage_dealt_pct`(造成的伤害 %)；`ap_max_delta` / `interest_off` 两个状态没用到就没做；
> 扭蛋机"晃它"之后不再回现场(选项本身不是可重复的)；挖到第 4 层塌方 = 结束；校验新增：纯负面事件不许有收益、带 repeat 的事件必须有普通的离开选项。

目标：往事件池里补一批**通用**事件（现在只有红之章限定的 2 个 + 兜底，第二章进去就只剩「寂静的街道」），
并覆盖三种新的事件形态：**可重复选择的选项**、**纯负面事件**、**高收益的通用事件**。顺带补两个紫之章能出的颜色事件。

---

## 0. 现状回顾（引擎现在能做什么）

- 事件 = 一幕实际建模的 3D 场景 + 杀戮尖塔式选项。数据 `tools/author_events.py`，文本 `author_loc.py` 的 `event(...)`，场景 `event_stage.gd` + `model_events.gd`。
- 池子：`common`(出现后整局移出) / `chapter` / `color`(同章不重复) / `exclusive` / `fallback`；稀有度 1~3，权重 6 / 3 / 1。
- 每章事件节点 2~5 个(权重 16%)，一局三章约 6~12 次事件 → 通用池至少要有 10 个以上才不会老见兜底。
- 选项：`requires`(现在只有 `truck_hp_above`、`ranged_attack_at_least`) + `outcomes`(按权重抽一个) + `effects`
  (`truck_damage` / `materials` / `gold` / `xp` / `ap` / `reveal` / `battle`)。选一次就结束，看完结果按「继续」离开。
- 经济口径(用来定数值)：开局 3 金；普通节点收入 3、精英 4 + 利息(每 10 金 1，最多 3)；刷新 2 金、升级 4 金；棋子 1~4 金；
  晶球期望：白 ≈ 2.5 金、蓝 ≈ 5 金、金 ≈ 10 金、虹 ≈ 8 金 + 一个 3 费；卡车耐久 100，修整回 30；一章行动力 19~24；零件 2~4 金。

## 1. 需要新增的引擎机制

### 1.1 可重复选择的选项（`repeat`）

```python
{"id": "pull", "repeat": {"max": 5},          # 最多选 5 次；省略 max = 不限(直到条件不满足)
 "requires": [...], "outcomes": [...]}
```

- `Run.event_state` 加 `picks: {选项 id: 次数}`。选了带 `repeat` 的选项 → 照常抽结果、结算效果、显示结果页；
  结果页的按钮不是「继续」而是**「回到现场」**(`ui.event.back`)，按下后 `option` 重置为 -1、回到选项列表(`picks` 保留)。
- 选项按钮上显示 **「第 n / N 次」**；次数用完 → 灰掉，条件行写"已经试过 N 次"。
- 每次的代价 / 结果可以随次数变：选项可写 `"by_pick": [outcomes 第 1 次, 第 2 次, …]`(超出用最后一组)；
  或者用新条件 `picked_below {option, value}` 把"挖到第 3 层"做成另一个选项。
- 带 `repeat` 的事件**必须有一个不带 `repeat` 的离开选项**(校验)。离开选项可以是免费的，也可以有收益(见下面的事件)。
- 场景可以随次数变(`EventStage.on_pick(option, n)`：扭蛋机灯光、坑越挖越深)。

### 1.2 新效果（`effects`）

| 效果 | 参数 | 说明 |
|---|---|---|
| `gold` | amount 允许负数 | 扣到 0 为止 |
| `materials` | 颜色允许负数 | 扣到 0 为止；`"half": "most"` = 扣掉最多的那种材料的一半 |
| `truck_heal` | amount / pct | 回复耐久 |
| `truck_max` | amount(可负) | 耐久上限 ±，上限低于当前耐久时一起压下去；最低 40 |
| `unit` | cost 或 id，star | 给一个商店池里该费用的随机棋子进仓库；仓库满了 → 折成卖价金币(结果文字另写一句) |
| `weapon` | max_cost 或 id | 给一把随机武器进武器库(走 `catalog.equipment_ids()`，和晶球同口径) |
| `orb` | tier, count | 直接按晶球表开(`_roll_loot_entry`)，开出的东西列在结果里 |
| `perm` | stat, amount, who: `random` / `strongest` / `cheapest` | 给一个棋子永久属性(roster 的 `perm`，和成长是同一套)；结果文字写出是谁 |
| `star_up` | max_cost | 把一个 1 星棋子(≤ max_cost，随机；候选和修整一样)升到 2 星 |
| `lose_unit` | who: `random` / `cheapest` | 失去一个棋子(场上 / 仓库都算；只有 1 个棋子时不生效，改为扣 5 金) |
| `lose_weapon` | — | 武器库里随机少一把(没有 = 不生效) |
| `part` | id 或 `random` | 一个卡车零件(零件箱满了折价) |
| `flag` | id, value, until: `chapter` / `next_battle` / `run` | 局内状态(见 1.4)，是"诅咒 / 祝福"的载体 |

### 1.3 新条件（`requires`）

`gold_at_least` / `materials_at_least {color, value}` / `level_at_least` / `ap_at_least` / `roster_at_least`(棋子数) /
`has_weapon`(武器库非空) / `bench_free`(仓库有空位) / `has_part` / `truck_hp_below`(纯负面事件的"保底"用) / `picked_below {option, value}`。
界面照旧：不满足 = 灰掉 + 一行红字说明现在是多少。

### 1.4 局内状态 `Run.flags`（诅咒 / 祝福）

`{id: {value, until}}`，由对应系统读取；换章 / 打完下一场自动清掉：

| id | 读取处 | 用途 |
|---|---|---|
| `next_battle_intensity` | `_make_encounter` | 下一场强度 ±n |
| `ap_max_delta` | `ap_max` | 本章行动力上限 ±n |
| `interest_off` | `interest()` | 本章没有利息 |
| `shop_odds_shift` | `roll_shop` | 本章商店概率表按 ±n 级查(祝福：按高一级抽) |
| `income_bonus` | 节点收入 | 本章每个节点 +n 金 |

HUD 左上角章节牌下面加一行小字显示当前的诅咒 / 祝福(图标 + 名字，悬停看说明)。

### 1.5 结果隐藏（赌博类选项）

选项可写 `"hidden": true`：选项下面不列出效果和概率，只写「？？？」；结果页照常。

### 1.6 场景：街景套件

每个事件都要一幕场景，12 个事件全部从零建模太重。做一个**街景套件** `scene: "roadside"`：废弃公路 + 路肩 + 远处的城市剪影 + 天色随章节主题，
每个事件只做**一个主角道具**(`props: [{model, pos, yaw}]`，按棋子比例建模，放在画面中心)。有战斗的事件仍然按规矩做专属战场。

## 2. 事件清单

稀有度：R1 常见 / R2 少见 / R3 稀有。"通用"= `common`(整局一次)。

### A. 可重复选择的选项

#### A1 扭蛋机 `gacha_machine`（通用，R2，场景：卷帘门半开的游戏厅门口，一台还亮着灯的扭蛋机）
"停电的街区里只有它还亮着。投币口下面压着一张手写的纸条：'只收金币'。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 投币(第 n / 5 次，n 次 = n+1 金) | 金币 ≥ 本次价格 | 隐藏结果。按晶球表：50% 白球、30% 蓝球、12% 什么都没有(机器吞币)、8% 金球 |
| 用力晃它 | 第 ≥ 2 次投币之后 | 40%：掉出一个白球 + 以后不能再投(机器坏了)；60%：卡车撞到机器，耐久 -4，机器坏了 |
| 走开 | — | 无 |

期望：前两次投币略赚(≈ +1 金)，第三次起持平、之后亏；5 次全投 ≈ -4 金但有 1/3 机会拿到金球。场景：每投一次扭蛋机灯转一圈、出口掉出一颗球。

#### A2 挖掘现场 `dig_site`（通用，R1，场景：路边一处被人挖了一半的坑，旁边插着铁锹和一台烧坏的挖掘机）
"有人在这里挖过东西，没挖完就走了。卡车的绞盘够不够？"

| 选项 | 条件 | 结果(`by_pick`，按层数) |
|---|---|---|
| 再挖一层(第 n / 4 层) | 卡车耐久 > 15 | 每层耐久 -3；第 1 层：有机物 +3；第 2 层：液态负熵 +4；第 3 层：60% +8 金 / 40% 一箱空的；第 4 层：40% 虹球 / 60% 塌方：耐久 -10、行动力 -1 |
| 收工 | — | 无(挖过 ≥ 1 层时结果文字写出一共带走了什么) |

纯粹的"再来一层"赌博：越深越贵、越深越值钱，第 4 层是明牌的高风险。

#### A3 负熵井 `entropy_well`（通用，R2，场景：公路旁一口发蓝光的井，井口结着冰、井绳自己在动）
"井里的水往上流。打上来的东西不是水。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 再打一桶(第 n / 3 次) | — | 液态负熵 +4；卡车耐久上限 -3(井水腐蚀车厢) |
| 让一个节点喝一口 | 仓库或场上有棋子 | 随机一个棋子：70% 永久 +8% 法强与攻击(`perm`)、30% 失去它(`lose_unit`；只有 1 个棋子时改为耐久 -10) |
| 盖上井盖 | — | 无 |

### B. 纯负面事件（没有赚的选项，玩家只能选"怎么亏"）

设计原则：损失在 3~8 金当量之间，绝不直接要命；每个事件至少一个选项**不吃卡车耐久**、至少一个选项**不吃金币**，
保证没钱 / 快死的人也有路走；耐久 < 20 时吃耐久的选项自动灰掉(`truck_hp_above`)。

#### B1 路障 `toll_gate`（通用，R1，场景：两辆横在路上的废车 + 一排沙袋，几个举着探照灯的黑影）
"路被堵死了。对方不想打，只想要东西。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 交钱 | 金币 ≥ 6 | 金币 -6 |
| 交一把武器 | 武器库非空 | 随机失去一把武器 |
| 硬闯 | 卡车耐久 > 20 | 卡车耐久 -12，行动力 -1(绕开路障的碎片) |
| 掉头 | — | 行动力 -2 |

#### B2 爆胎 `blowout`（通用，R1，场景：主角就是**自己的卡车**停在路肩，右后轮瘪了，一个节点蹲在旁边）
"砰的一声。所有人都看向同一个方向。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 换备胎 | — | 行动力 -2 |
| 用轮毂开 | 卡车耐久 > 20 | 卡车耐久 -10 |
| 拆零件顶上 | 零件箱非空 | 失去一个随机零件 |

#### B3 变质的补给 `spoiled_supplies`（通用，R1，场景：车厢门开着，几个材料罐倒在地上冒烟）
"车间的密封罐不知道什么时候开了一道缝。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 倒掉坏的那批 | — | 最多的那种材料 -50% |
| 抢救(花时间分拣) | — | 行动力 -1，三种材料各 -1 |
| 不管它 | — | 诅咒：本章车间材料全部 -1 的概率…(太隐蔽) → 改成：卡车耐久 -6(罐子在车厢里炸了) |

#### B4 余烬风暴 `ash_storm`（颜色：红，R2，场景：街景套件 + 满屏横飞的余烬，能见度只剩几米）
"风把整座城市的灰烬都卷起来了。"

| 选项 | 条件 | 结果 |
|---|---|---|
| 顶风开 | 卡车耐久 > 20 | 卡车耐久 -8 |
| 停车等 | — | 行动力 -2 |
| 关掉所有仪器 | — | 诅咒 `next_battle_intensity +6`(下一场敌人趁着风暴摸过来) |

### C. 高收益的通用事件（不限章节；收益 ≈ 2~3 个蓝球，用条件或风险换）

#### C1 失落的军火库 `lost_armory`（通用，R3，场景：公路边一扇半埋在土里的钢门，门缝透出灯光）

## 3. 数值口径汇总

| 形态 | 单次损益范围(金当量) | 备注 |
|---|---|---|
| 可重复选项 | 前 1~2 次 +1~+2，之后 -1~-3 | 总上限由 `max` 限死；最后一次是明牌的高风险 |
| 纯负面 | -3 ~ -8 | 至少一个选项不吃耐久、一个不吃金币；耐久 < 20 时耐久选项灰掉 |
| 高收益通用 | +10 ~ +18 | 用等级 / 攻击力 / 金币 / 行动力换，或 50% 的赌 |
| 颜色事件 | +3 ~ +6 | 和现有的红之章事件同档 |

稀有度分布：R1 ×5(toll_gate / blowout / spoiled_supplies / dig_site / frozen_traveler)，R2 ×6，R3 ×2(lost_armory / orb_rain)。
按权重 6 / 3 / 1，一章 3~4 次事件里大约 1 次负面、1 次可重复、0.5 次高收益。

## 4. 实现顺序与工作量

1. 引擎(1 天)：`repeat` + `picks` + 「回到现场」；新效果 / 条件 / `Run.flags` + 五个读取点；`hidden`；校验(`Events.validate`)补全；
   `test_events.gd`：重复选项的流程、次数上限、负数效果不越界、`lose_unit` 保底、flags 到期清除。
2. 数据 + 文本(半天)：13 个事件进 `author_events.py` / `author_loc.py`(中英)。
3. 场景(1~2 天)：街景套件 `roadside` + 13 个主角道具(`model_events.gd`)；爆胎用现成的卡车模型。
4. 验证：`./run_tests.sh`、`./run_ui_test.sh`(扭蛋机的重复流程 + 一个负面事件截图)、`campaign_bench`(看事件对三章通关率的影响：
   目标是负面事件不把红之章首领通关率拉低 5 个点以上)。

## 5. 需要你拍板的点

1. **可重复选项的交互**：结果页按「回到现场」回选项列表(我的方案)，还是结果页上直接再放一个「再来一次」按钮？
